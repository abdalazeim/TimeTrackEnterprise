# نظام متابعة حضور وغياب التلاميذ بالباركود والرسائل القصيرة

تطبيق مؤسسي مبني على **Django 5** يعمل محليًا على Windows أو على خادم داخل المؤسسة، ويدعم ثلاث لغات (العربية RTL، الإنجليزية والفرنسية LTR).

يجمع النظام بين:

- استيراد ذكي لقوائم التلاميذ من Excel وXLS وHTML، مع كشف الأعمدة تلقائيًا.
- تسجيل الحضور بالباركود عبر ماسح HID أو كاميرا الحاسوب أو هاتف مقترن.
- طباعة بطاقات التلاميذ وملصقات الباركود والطوابع بمقاسات A4 دقيقة.
- رصد الغياب بعد مهلة الفترة وإرسال SMS/واتساب للأولياء بموافقة صريحة.
- تقارير يومية وشهرية قابلة للتصدير إلى Excel والطباعة.
- تبرير الغياب، وورقات دخول وخروج موقّعة برمز QR.
- **مزامنة** بين أجهزة المؤسسة وتطبيق أندرويد عبر بروتوكول `/api/sync/` مع كشف التعارضات.

تُحفظ البيانات محليًا في قاعدة SQLite واحدة، ولا يتصل التطبيق بأي خدمة خارجية إلا عند إرسال رسائل فعلية أو فحص تحديث موقّع.

## الواجهة واللغات

| اللغة | الرمز | الاتجاه |
| --- | --- | --- |
| العربية (افتراضية) | `ar` | RTL |
| الإنجليزية | `en` | LTR |
| الفرنسية | `fr` | LTR |

- تُبدَّل اللغة من الشريط العلوي أو بزيارة `/language/en?next=/`، ويُحفظ الاختيار في الكوكي `attendance_lang`.
- تُترجَم نصوص الواجهة والرسائل والتقارير فقط؛ تبقى أسماء التلاميذ والأقسام ومحتوى الرسائل كما أدخلها المستخدم.
- كل الأرقام تُعرض بالأرقام الغربية `0-9`، وتُحوَّل الأرقام العربية/الفارسية عند الإدخال.
- الخط **Cairo** مضمّن محليًا في `static/fonts/`، ولا يُطلب أي مورد من الإنترنت.
- كتالوجات الترجمة: `apps/core/locales/{en,fr}.json`، وتُبنى بـ `python scripts/build_locales.py`.

## المستخدمون والأدوار

- عند أول تشغيل يُنشأ حساب `admin` نشط **بدون كلمة مرور**. سجّل الدخول فورًا واضبط كلمة مرور قوية من **الإعدادات ← المستخدمون**.
- تُحفظ كلمات المرور بصيغة **Werkzeug PBKDF2** في جدول `users` (متوافق مع النسخة القديمة).
- **مدير (admin):** كل العمليات، الإعدادات، المستخدمون، النسخ الاحتياطي، تثبيت التحديثات، مراجعة تعارضات المزامنة.
- **مستخدم (user):** البوابة، التلاميذ، الاستيراد، الطباعة، سجل الحضور، التقارير، الرسائل.
- يجب أن يبقى مدير نشط واحد على الأقل، ولا يمكن للمستخدم حذف حسابه أو تعطيله أو إزالة دوره.
- الجلسة صالحة 12 ساعة، وتُخفى كلمة المرور دائمًا، وتُفرض مهلة بعد محاولات الدخول الفاشلة.
- تُسجَّل محاولات الدخول الفاشلة (5 لكل اسم مستخدم/عنوان خلال 5 دقائق) إضافة إلى حدّ عام لكل عنوان IP.

## التشغيل السريع

```bat
run.bat
```

يقوم السكربت بإنشاء `.venv`، تثبيت المتطلبات، تطبيق الترحيلات، ثم تشغيل الخادم المكتبي على:

```text
http://127.0.0.1:8765/
```

### التشغيل اليدوي

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe desktop\launcher.py
```

أو أثناء التطوير:

```bat
.venv\Scripts\python.exe manage.py runserver
```

### خيارات المشغّل المكتبي

```text
--host 127.0.0.1      عنوان الاستماع (محلي افتراضيًا)
--port 8765           المنفذ المفضل؛ يُبحث عن منفذ حر عند انشغاله
--data-dir PATH       مجلد البيانات
--no-browser          عدم فتح المتصفح
--no-scheduler        تعطيل الرصد التلقائي (للتجارب)
--version             عرض الإصدار
```

> لا تضبط `--host 0.0.0.0` إلا داخل شبكة موثوقة. للتعرض للإنترنت استخدم إعدادات `production` خلف Nginx وTLS (انظر `docs/deployment/README.md`).

## البيانات والنسخ الاحتياطي

مجلد التشغيل الافتراضي هو `data/` بجوار المشروع (أو بجوار `TimeTrackEnterprise.exe` في النسخة المحمولة):

```text
data\
├── TimeTrackEnterprise.db  قاعدة البيانات (Django + الجداول القديمة)
├── photos\            صور التلاميذ
├── uploads\           الشعار والطابع
├── logs\app.log       سجل دوّار
├── tmp\               ملفات الاستيراد المؤقتة
├── updates\           حزم التحديث
└── backups\           النسخ الاحتياطية
```

يمكن تغييره بـ `--data-dir` أو `ATTENDANCE_DATA_DIR`.

### نسخة احتياطية

- من الواجهة: **الإعدادات ← النظام ← تنزيل نسخة احتياطية** أو `GET /api/system/backup`.
- من الطرفية:

```bat
.venv\Scripts\python.exe scripts\backup.py --keep 14
```

- الاستعادة: أوقف التطبيق ثم:

```bat
.venv\Scripts\python.exe scripts\restore.py backups\TimeTrackEnterprise-20261031-120000.db
```

اسم ملف قاعدة البيانات هو `TimeTrackEnterprise.db`. عند أول تشغيل، ينسخ النظام قاعدة `attendance.db` القديمة بأمان إلى الاسم الجديد ويحتفظ بالأصل كنسخة رجوع. لا تفتح قاعدة البيانات بأدوات خارجية أثناء التشغيل.

## الاستيراد الذكي

من صفحة **الاستيراد**: ارفع `.xlsx` أو `.xls` أو جدول HTML بامتداد `.xls`، راجع اكتشاف الأعمدة، ثم وافق على الاستيراد. تكرار رقم التعريف يُحدّث بيانات التلميذ مع الحفاظ على سجلاته.

- الحقول: رقم التعريف (إلزامي)، اللقب، الاسم، تاريخ الميلاد، القسم، هاتف الولي، مسار الصورة.
- النماذج: `static/samples/students_sample.xlsx` و`.xls`.
- الحد الأقصى: 50,000 صف وحجم 25 ميغابايت، والصور تُنسخ بالبصمة إلى `data/photos/`.

## بوابة الحضور

- يلتقط الماسح (USB HID) الإدخال السريع تلقائيًا، ويمكن تشغيل الكاميرا من الزر المخصص.
- الفترة تُختار تلقائيًا حسب الوقت، ويمكن تثبيتها يدويًا.
- قبل `حد الحضور` يُسجل «حاضر»، وبعده «متأخر»، مع منع المسح المكرر خلال مدة قابلة للضبط.
- وصول تلميذ سُجل غائبًا يحدّث حالته ويلغي رسالة SMS المعلّقة إن لم تُرسل.
- تعرض البطاقة الفورية الصورة والحالة وإحصاء الفترة.

## الغياب والرسائل

1. بعد `حد الغياب` تُغلق الفترة يدويًا أو تلقائيًا، فيُدرج `ABSENT` لكل تلميذ نشط لم يُسجَّل.
2. من **الحضور والغياب** أو **قائمة SMS** تُعاين المستفيدين، ثم يُفعَّل مربع الموافقة قبل الإرسال.
3. الإرسال في الخلفية مع تتبع التقدم وإعادة المحاولة، وتبرير الغياب يلغي الرسائل المعلّقة.

### البوابات

- **بوابة أندرويد محلية:** تستقبل JSON بحقلي `phone` و`message`، محمية بـ `X-Api-Key`، وتُقرن برمز 4 أرقام من الإعدادات.
- **واجهة سحابية:** رابط وترويسات وقالب JSON بـ `{{phone}}` و`{{message}}` و`{{api_key}}`.
- **WhatsApp يدوي:** روابط `wa.me` جاهزة للمراجعة والإرسال اليدوي.
- **Meta WhatsApp Cloud API:** Phone number ID، رمز دائم، اسم القالب ولغته، وإصدار Graph API.
- **وضع الاختبار مفعّل افتراضيًا** ويحاكي الإرسال دون شبكة.
- متغيرات قالب الرسالة: `[اسم_المؤسسة]`، `[اسم_التلميذ]`، `[القسم]`، `[اسم_الفترة]`، `[التاريخ]`، `[السنة_الدراسية]`.

## ورقات الدخول والخروج

- `/entry-slip`: مسح بطاقة تلميذ غائب، اختيار السبب والفترة، ثم إصدار إيصال حراري موقّع.
- يحوّل الإصدار سجل الغياب إلى «حاضر» أو «متأخر» ويلغي الرسائل المعلّقة.
- ثلاثة قوالب طباعة: كامل (80 مم)، متوسط (80 مم)، صغير (58 مم).
- `/entry-slip/verify?code=...` يتحقق من توقيع HMAC-SHA256 ويرفض أي تعديل.
- `/exit-slip`: إصدار ورقة خروج، إعادتها، والتحقق منها، مع QR وCode128.
- تُسجَّل كل ورقة وعدد نسخ الطباعة، ويمكن إعادة الطباعة من القائمة.

## الطباعة والتقارير

- **استوديو الطباعة** (`/print/sheet`): بطاقات CR80 `85.6 × 54 مم` (8 أو 10 على A4)، أو ملصقات 24/30، مع الشعار والصورة وQR والطابع وألوان قابلة للتخصيص.
- للطباعة الدقيقة: A4، 100% أو «الحجم الفعلي»، بلا هوامش إضافية وبلا «ملاءمة الصفحة».
- تقارير يومية وشهرية JSON، وتصدير XLSX، وصفحة طباعة مستقلة `/reports/print`.

## تطبيق TimeTrackEnterprise Android

يتصل تطبيق Flutter `TimeTrackEnterpriseAndroid` بخادم Django عبر `/api/mobile/*`:

- في الشبكة المحلية، شغّل خادم سطح المكتب على جهاز المدرسة واستخدم عنوان LAN المطبوع عند التشغيل، مع اتصال الهاتف والحاسوب بالشبكة نفسها.
- في الاستضافة، استخدم عنوان HTTPS للنطاق وأضفه إلى `ATTENDANCE_ALLOWED_HOSTS`. يرفض التطبيق عناوين HTTP العامة والتحويلات.
- يصدر المدير رمز الموظف من **الإعدادات ← المستخدمون**، ويسجل ولي الأمر برقم الطالب الوطني ذي 12 رقمًا.
- تتم مزامنة قائمة الطلاب والفترات والمسحات دون اتصال، وتُحفظ الإشعارات في الخادم.

بوابة SMS/الماسح التي يستضيفها التطبيق على الهاتف اتصال محلي منفصل: يمكن لخادم المدرسة الوصول إليها عبر LAN، أما خادم الاستضافة فلا يستطيع بدء اتصال إلى عنوان الهاتف الخاص خلف NAT. يلزم VPN أو نفق أو آلية ترحيل/سحب صادرة لاستخدام بوابة الهاتف عن بعد.

يوجد بروتوكول `/api/sync/` عام مستقل لمزامنة كيانات البيانات، لكنه ليس API تسجيل الدخول أو مزامنة الحضور الذي يستخدمه تطبيق TimeTrack الحالي. راجع `docs/api/README.md` لعقد واجهات النظام والمحمول.

## التحديثات الموقّعة

- خادم التحديثات الافتراضي: `https://fetsync.org/Update/latest.json`.
- يتحقق البرنامج من توقيع **Ed25519** لملف `latest.json` بالمفتاح العام المضمّن، ثم من **SHA-256** وحجم الملف.
- يبدأ التنزيل تلقائيًا عند التفعيل، ويُثبَّت فقط عندما يكون النظام خاملًا، ثم يُعاد التشغيل.
- المدير يستطيع الفحص والتثبيت يدويًا من **الإعدادات ← تحديثات النظام**.
- المفتاح الخاص `secrets/update_signing_key.pem` لا يُرفع إلى المستودع. المفتاح العام في `apps/core/config.py`.

### نشر إصدار

1. ارفع `APP_VERSION` في `apps/core/config.py` وأعد بناء الملف التنفيذي والتثبيت.
2. أنشئ `latest.json`:

```bat
.venv\Scripts\python.exe scripts\sign_update.py ^
  --version 1.1.20 ^
  --notes "ملاحظات الإصدار" ^
  --portable dist\TimeTrackEnterprise.exe ^
  --setup dist\TimeTrackEnterprise_Setup_1.1.20.exe ^
  --out dist\update\latest.json
```

3. ارفع الملف والبناءات إلى المسارات التي يطبعها الأمر.

## النشر على خادم

- **Docker + Nginx + gunicorn:** `deployment/docker/docker-compose.yml` مع `deployment/nginx/timetrack.conf`، والخطوات الكاملة في `docs/deployment/README.md`.
- **Linux/systemd:** gunicorn بإعداد `deployment/gunicorn/gunicorn.conf.py` خلف Nginx.
- **Windows Server:** waitress خلف IIS/Nginx.
- اضبط `DJANGO_SETTINGS_MODULE=config.settings.production` و`ATTENDANCE_SECRET_KEY` و`ATTENDANCE_ALLOWED_HOSTS` و`ATTENDANCE_CSRF_TRUSTED_ORIGINS`، وفعّل TLS.
- شغّل `python manage.py check --deploy --settings=config.settings.production` قبل النشر.
- المهام الخلفية (إغلاق الفترات، فحص التحديثات، نبض البوابة) تعمل داخل عملية واحدة فقط بفضل قفل `DATA_DIR/scheduler.lock`. لإبقاء عمّال الويب خاملين اضبط `ATTENDANCE_BACKGROUND_JOBS=0` وشغّل `python manage.py run_scheduler` كخدمة مستقلة.

## الأمان

- استضافة محلية افتراضيًا، و`/admin/` مقيد بـ loopback في نسخة سطح المكتب.
- CSP صارم، `X-Frame-Options: DENY`، `nosniff`، و`Referrer-Policy`.
- كل تعديل عبر `/api/` يتطلب `X-Requested-With: StudentAttendance`، ومسارات المزامنة تتطلب رمز جهاز.
- `Secure` وHSTS في الإنتاج فقط، وكلمات المرور PBKDF2، وجلسات HttpOnly.
- الصور تُفحص بالبصمة السحرية وتُسمّى بالتجزئة، وصور التلاميذ تتطلب جلسة دخول.
- راجع `docs/security/README.md` و`docs/reviews/security.md`.

## استكشاف الأخطاء

| المشكلة | الحل |
| --- | --- |
| المنفذ 8765 مشغول | يبحث المشغّل عن منفذ حر ويعرضه في السجل؛ أغلق النسخة الأخرى. |
| لا تفتح نافذة المتصفح | افتح الرابط المطبوع يدويًا، وتأكد من وجود Edge أو Chrome. |
| الكاميرا لا تعمل | استخدم ماسح HID أو امنح إذن الكاميرا على localhost. القارئ مضمّن. |
| رسالة SMS لا تُرسل | وضع الاختبار مفعّل افتراضيًا؛ اضبط بوابة صالحة ثم عطّله ووافق على الإرسال. |
| «قاعدة البيانات مقفلة» | أغلق النسخ الأخرى ولا تفتح الملف بأدوات خارجية أثناء الكتابة. |
| خطأ في الترحيلات | نفّذ `python manage.py migrate` ثم أعد التشغيل. |
| اختلاف مقاسات الطباعة | اختر A4 و100% وعطّل Fit to page. |
| الواجهة لا تتغير لغتها | أعد تشغيل الخادم بعد بناء الترجمات، واسمح بكوكي `attendance_lang`. |
| تعارض مزامنة | راجع **الإعدادات ← المزامنة** واختر النسخة المحلية أو الخادم أو الدمج. |
